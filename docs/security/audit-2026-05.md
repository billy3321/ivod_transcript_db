## 接受的剩餘 CVE 與評估

剩餘 8 個皆為 **moderate**（無 high / critical），分類如下：

### 0. qs 透過 @modelcontextprotocol/sdk → express [moderate]
- **CVE**: qs.stringify crashes with TypeError on null/undefined entries in comma-format arrays
- **使用情境**: Express 內部使用，本專案未直接呼叫 `qs.stringify({encodeValuesOnly: true})`
- **實際風險**: 低（觸發條件需特殊 stringify 設定，不適用本專案）
- **處置**: 接受；等 @modelcontextprotocol/sdk 上游 bump

### 1. bodybuilder 透過 lodash.unset@4.5.2 [moderate]
- **CVE**: prototype pollution in `_.unset`
- **使用情境**: `lib/elastic.ts` 透過 bodybuilder 建構 ES query；輸入皆為程式內部控制，無 user-supplied object path
- **實際風險**: 低
- **處置**: 接受
- **長期方案**: 考慮把 bodybuilder（已多年未維護）換成手寫 ES query body 或其他 maintained 函式庫

### 2. cypress → form-data [moderate]
- **CVE**: form-data unsafe random
- **使用情境**: cypress 是 **devDependency**，僅 E2E 測試用，不進 production bundle
- **fix 建議**: cypress@13.14.2（從 14.x 降版，明顯是 advisory 不準）
- **處置**: 接受；production 不受影響
- **長期方案**: 等 cypress 主版本釋出含 form-data 升級的 patch

### 3. next 透過 postcss@8.4.31（內部） [moderate]
- **CVE**: postcss XSS via unescaped `</style>` in CSS stringify
- **使用情境**: postcss 處理我們自己寫的 CSS 與 Tailwind 輸出；不處理 user-supplied CSS
- **fix 建議**: next@9.3.3（從 15.5.18 降版六個 major version，明顯錯誤）
- **處置**: 接受；等 Next.js 上游 bump 內部 postcss
